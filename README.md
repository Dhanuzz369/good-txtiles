# GoodBiz Apparels — export website

Static multi-page site generated by a small Node script. No dependencies.

```
src/data.mjs     company details, catalogue, HSN codes, FAQs  ← edit this
src/markets.mjs  export market pages (rules, FAQs, official sources)
src/guides.mjs   long-form guides
src/build.mjs    page templates, schema, CSP, sitemap, robots, llms.txt, llms-full.txt
src/assets/      styles, script, self-hosted fonts, images, favicon, logo
public/          generated site (not committed; the build writes it)
vercel.json      Vercel build, trailing-slash URLs, security headers
SEO-STRATEGY.md  keyword map, architecture, ads + cold email, launch checklist
versions/        earlier snapshots (v1, v3 3D, v4 before fonts and outerwear change)
```

## Deploy (Vercel)
Every push to `main` on GitHub deploys automatically. Vercel runs `node src/build.mjs` and serves `public/`. The canonical domain is `https://www.gbizclothing.com` (`SITE.url` in `src/data.mjs`); canonicals, the sitemap, `robots.txt`, `llms.txt` and structured data all use it. `vercel.json` 308-redirects `good-txtiles.vercel.app` to it, sets security headers and caches the fingerprinted CSS/JS (`/assets/v/`) and fonts for a year.

## Design ("Tech pack")
Greige cotton paper, indigo dye, hairline spec-sheet rules. Cabinet Grotesk for display and Switzer for text (both Fontshare, ITF Free Font License), IBM Plex Mono for codes and labels (SIL OFL), all self-hosted in `src/assets/fonts/`. Icons are Phosphor (MIT) outlines drawn as CSS masks. Emphasis uses a highlighter-tape underline instead of italics. Tokens are at the top of `src/assets/styles.css`.

## Build

```bash
node src/build.mjs
```

Use `SITE_URL=https://other.domain node src/build.mjs` to build for another domain. The hero's animated layout is chosen by a tiny inline script in `<head>` before first paint, so the page never shifts as it loads; every inline script is allowed by a SHA-256 hash in the page's Content-Security-Policy, which the build computes.

Preview locally: `cd public && python3 -m http.server 4322`, then open http://127.0.0.1:4322

## Before going live
1. Enquiries go to clothing@goodbizglobal.com (`SITE.email`, and `NOTIFY_EMAIL` in `tools/enquiry-sheet.gs`). After changing the script, paste it into Apps Script and use Deploy → Manage deployments → New version.
2. Production is described as partner factories in India, managed by GoodBiz Apparels. Keep that wording consistent with goodbizglobal.com.
3. Still to fill in `SITE` (each one appears on the site automatically once set, and stays hidden until then): `legalName`, `iec`, `gstin`, `rcmc`, `certifications`, `moq`, `founded`, and a street address.
4. HSN codes were checked against India's ITC-HS tariff on 8 November 2026 (polos 61051020, jackets 62013090 and 62014090, silk shirts 62059019, cotton babywear 62092090). Have your customs broker confirm them.
5. Add GA4 / Google Ads IDs in `SITE.ga4` and `SITE.adsConversion`, and the Search Console / Bing tokens in `SITE.googleVerification` / `SITE.bingVerification` if you verify by meta tag.
6. Replace the stock garment photos with your own (see "Product photos"). Until then, photos are labelled as representative.

## Enquiry form
A 7 step form (products, route, spec, quantity, destination and price basis, contact, review); contact details are asked last. It appears on the home, contact, family, service and export market pages. Until a Google Sheet is connected it sends the finished enquiry by email or WhatsApp from the buyer's own device.

### Connect a Google Sheet
1. Open the Sheet → Extensions → Apps Script → paste `tools/enquiry-sheet.gs` → Save.
2. Run `setup` once and approve the permissions (Sheet + Gmail for the alert email).
3. Deploy → New deployment → Web app → Execute as: Me → Who has access: Anyone → Deploy. Copy the `/exec` URL.
4. Put the URL in `SITE.formEndpoint` in `src/data.mjs` and run `node src/build.mjs` (or build with `FORM_ENDPOINT=<url> node src/build.mjs`).

Every enquiry then lands as a row in the "Enquiries" tab (with a Status dropdown) and the team gets an alert email with Reply set to the buyer. A hidden spam trap drops bot submissions, and buyer text that starts with = + - @ is stored as plain text, never as a formula.

Landing pages: `/lp/garment-manufacturer/` (Google Ads) and `/lp/sourcing/?name=…&company=…` (cold email). Both are noindex.

Photos: Unsplash, used under the Unsplash License and labelled as representative. Every image has 200/400 (cut-outs), 400/700 (lineups) or 700 px (photos) copies for `srcset`, plus a 1200×630 JPEG share image in `img/og/`; regenerate them with `cwebp` and `sips` if you replace a photo.

## Product photos
Each product line has a colourway lineup photo in `src/assets/img/line/` (one per product, named after the product). They are generated by `tools/lineup.py` from the garment cut-outs in `tools/bases/`, recoloured and hung in front of the factory photo. To regenerate after changing colours or garments:

```bash
python3 -m pip install pillow numpy
python3 tools/lineup.py _ .
```

## 3D product cut-outs
Garment cut-outs live in `src/assets/img/cut/` (WebP with transparency); each product family's cut-out and swatch colour are set in `LOOKS` at the bottom of `src/data.mjs`.

To cut out your own product photo (macOS 14+, uses built-in subject lifting):

```bash
swiftc -O tools/lift.swift -o tools/lift
tools/lift my-shirt.jpg my-shirt.png
```

Shoot garments on a plain background, one item per photo. `tools/split.swift` writes each detected subject separately if a photo has several.
